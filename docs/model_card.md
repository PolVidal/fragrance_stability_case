# Model card — Fragrance shelf-life stability predictor

## What it does
For each production batch, from the sensor readings available **before the separation step**, it gives:
- a **predicted shelf-life stability** in months;
- a **90% interval** for that value;
- a **traffic light**: red (almost surely Technical grade, < 20 months), amber (uncertain: check in the lab), green (almost surely Industrial or better);
- an **out-of-range warning** when a sensor lies outside the conditions the model was trained on;
- an **explanation**: how many months each sensor added or removed versus the average batch.

Code: `src/fragrance/model.py` (`StabilityPredictor`). Built and evaluated in `notebooks/04_model.ipynb`. Saved package: `models/stability_predictor.joblib`, regenerated by running the notebook.

## Intended use
Early warning for the Quality team at production time: downgrade red batches, release green batches, prioritise amber batches for the lab. **It does not replace the lab test**, which remains the ground truth and feeds the model.

## Inputs
Six sensors: reaction temperature (°C), vessel pressure (bar), refractive index, pH, mixing torque (N·m), mass flow (kg/h). Missing values are allowed. Density is not used: it adds nothing (MAE change ≤ 0.003 months) and is only available after separation. Plant, reactor and date are not inputs. The reactor is used only for batches with no sensor data at all (fallback to the reactor's training average).

## Model
- Prediction: LightGBM gradient boosting (600 trees, learning rate 0.05, 31 leaves, at least 100 batches per leaf), chosen by a protocol fixed before any model was run (notebook 04).
- Interval: conformalized quantile regression (two LightGBM quantile models at 5% and 95%, calibrated on unseen batches).
- Out-of-range flag: any sensor outside the 0.1%–99.9% range of the training data.
- Explanations: SHAP values (TreeSHAP).

## Data
Clean table from `notebooks/02_cleaning.ipynb` (sentinel codes set to missing, Fahrenheit converted, timestamps parsed). Fitted on April 1 – May 29 2023 (166,026 batches), calibrated on May 30 – June 8 (28,358), tested on June 9 – 29 (60,730, never used for any choice).

## Performance (test period, June 9 – 29)
| | Value |
|---|---|
| Mean absolute error, batches with sensor data | 0.73 months (R² 0.80) |
| Mean absolute error on Technical batches (< 20 months) | 0.51 months |
| Reactor-average baseline | 1.63 months |
| 90% interval coverage | 90.0% overall; 90.4 / 89.4 / 89.1% with 0 / 1 / 2+ sensors missing |
| Mean interval width | 2.7 months (2.3 with all sensors, 4.1 with two or more missing) |
| Traffic light | red 11.6% of batches (99.6% truly Technical); green 46.3% (0.5% Technical); amber 42.1% (42% Technical, 60% of all Technical batches) |
| Flag "prediction < 20" | recall 72.5%, precision 85.5%, ROC-AUC 0.947 |
| Batches without sensor data | MAE 1.66 months, coverage 90.8%, always amber |

Stable across three walk-forward validation folds (MAE 0.72–0.74) and across the four test weeks. XGBoost, CatBoost, a neural network, tuning and an ensemble all reach the same ~0.73: this is the limit of what the six sensors can explain.

## Limitations
- **New conditions.** The model cannot predict beyond what it has seen. Trained before the May 8 event, it was 1.1 months too optimistic on the event batches. The out-of-range flag caught 91% of them in that test. Monitor with control charts and retrain regularly.
- **Regression to the mean.** Very good batches are underestimated (Perfumery-grade batches by about 1.1 months; interval coverage 83% for them), and Technical batches are slightly overestimated (+0.4 months). That is why decisions use the interval, not the point prediction.
- **Missing sensors** reduce accuracy (MAE 0.64 with all sensors, 1.05 with two or more missing); intervals widen accordingly.
- **Association, not causation.** Explanations describe what the model uses, not proven causes. Torque, for example, may reflect the mixture's viscosity as much as the agitator setting.
- **Synthetic data, 90 days.** To be revalidated on real data and over longer periods. In real use, lab results arrive with a delay, so retraining lags behind production.

## Maintenance
Retrain on the most recent lab results (e.g. monthly), recalibrate the interval on the latest unseen weeks, and check coverage (should stay near 90%) and MAE against new lab results. Investigate any rise in out-of-range flags: it means the process has moved.
